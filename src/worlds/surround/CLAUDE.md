# Surround — Claude instructions

Player-vs-computer recreation of Atari's Surround (1977). Rebuilt 2026-07-26 as a
real-time 3D arena on James's ask ("bring it up totally cool to 2026 — 3D effects,
a neat HUD, cool lighting"). Light-walls rise behind each rider on a glass floor,
under a containment field, through a bloom/tone-map chain.

## Docs

- `changelog.md` — session history, newest first.

## Files

- `game-core.js` — ALL game logic (grid, movement, collisions, the three AI
  levels), pure module: no DOM, no timers, no Math.random. Shared verbatim with
  the sim; keep it pure or the sim lies. **The 3D rebuild did not touch it.**
- `render3d.js` — the whole picture, and nothing else: no game rules, no DOM, no
  audio, no input. three.js (importmap → `../../lib/three/three.module.js`).
- `territory.js` — pure: BFS ownership of every empty cell. Feeds the floor wash
  and the HUD meter. Deliberately not in game-core.js (sim contract) and not in
  render3d.js (presentation only).
- `game.js` — the shell: match flow, input, HUD, sound synthesis, tuner, presets.
- Sim: `node tmp/surround/sim.mjs` — 7139 assertions on the real core. RUN IT
  after touching game-core.js.

## The look-dev harness — use it

`tmp/surround/lookdev.html` (served: `http://127.0.0.1:4174/tmp/surround/lookdev.html`)
is a **silent** AI-vs-AI page driving `render3d.js` with live sliders for every
look parameter. It is where the picture gets judged before it flies. Keep it.

It surfaces every error on the page (window.onerror + console.error → red
banner), and exposes `globalThis.LAB = { arena, state, tick, ... }` so a checker
can drive frames when rAF is frozen — the preview pane stops compositing when it
is not displayed, so `LAB.tick()` + `LAB.arena.render()` is the only way to
compile shaders and read pixels back headlessly.

`tmp/surround/smoke.html` is generated by `node tmp/surround/make-smoke.mjs`: the
real world page with the shared sound control swapped for a no-op stub, so the
full shell can be loaded in the pane without ever creating an AudioContext
(house rule: never load a sound world in the preview pane). It also wraps rAF so
`SMOKE.pump(frames, dtMs)` steps the real match loop. **Regenerate it after
editing index.html.**

## World-specific rules

- Draft status: no drift wiring, no `world.json`, not in the registry yet. Those
  arrive at ship time (and remember the registry generator includes drafts —
  hand-check the diff).
- AI levels are 1 DRIFTER (wobbly wall-avoider), 2 HUNTER (greedy flood-fill
  space), 3 ORACLE (Voronoi territory while contested, wall-hugging space-filler
  once the arena splits — the separated mode is what makes it strong; don't
  remove it). Sim asserts hard > medium > easy; keep that ordering when tuning.
- Simultaneous crash = draw, no point (classic Surround behavior).
- **No screen shake, and the camera never chases a rider** — James gets motion
  sick. Crash feedback is flash + sparks + a floor shockwave + a bloom spike.
  The camera frames the whole arena, always; idle drift defaults to a barely
  perceptible breath and is on a slider.
- Speed ramps within a round (+3.5%/s, capped +90%); the hum pitch tracks it and
  the engine note pans with the player's x position.
- Every control panel dismisses on `pointerdown` outside it (all-worlds rule).
- Pause: `P` / `Esc` / the button; `Space` resumes; auto-pauses on window blur
  and tab hide. Resuming mid-round always goes through an 800 ms "GO" beat —
  don't remove it, resuming instantly kills a rider that paused mid-corner.
- Forfeit is deliberately two-step (arm → confirm, arm expires after 3 s) and
  concedes the whole match, powering down the player's wall first. At match end
  the same button becomes NEW MATCH and the pause button hides.
- Tuner has two tabs. PLAY (speed, arena, opponent, first-to, territory read-out)
  — arena/opponent/first-to restart the match by design. LOOK (14 render knobs)
  is live and file-backed: presets go to `assets/presets.json` through
  `PUT /api/worlds/surround/presets`, so **saving a preset is telling Claude**.

## Renderer notes (hard-won)

- **Never call `pow()` on a value that can go negative.** A single NaN pixel gets
  smeared across the entire frame by the bloom blur and the screen goes black.
  All `pow` bases are clamped, and the bright-pass filters NaN with `x >= 0.0`
  (NaN fails every comparison) and clamps Inf. Keep both guards.
- `half` is a reserved word in GLSL — it will not compile as a variable name.
- **A `<canvas>` is a replaced element.** `position: absolute; inset: 0` does
  NOT stretch it — with `width: auto` it stays at its intrinsic 300x150 in the
  top-left corner. It needs an explicit size in CSS and/or `setSize(w, h, true)`.
  This world does both, sized from `window.innerWidth/innerHeight` (clamped
  above zero — a zero-size window puts NaN through `camera.aspect` and silently
  kills the render loop).
- One geometry per rider serves three materials via a `uMode` uniform: the
  vertical ribbon, the hot rail capping it, and the soft floor bleed. The same
  geometry is drawn again in a `scale.y = -1` group for the under-glass
  reflection. Wall height, strip width and the age-cooling are all uniforms, so
  they stay live-tunable without rebuilding geometry.
- Trail points carry a mitred perpendicular (`aOff`) so 90° corners keep constant
  width. The last point rides the interpolated head every frame, so the wall
  extends continuously instead of popping a cell at a time.
- Walls are `NormalBlending` with `depthWrite: true` so the arena reads
  spatially; rails, bleeds and reflections are additive with `depthWrite: false`
  and explicit `renderOrder` (reflections → floor → walls → rails → sparks).
- **Camera framing is solved, not guessed.** `_fitDistance` projects the arena's
  eight corners and scales the distance by the overshoot until it converges,
  filling `FIT_X`/`FIT_Y` of the frame. Don't replace it with a closed-form
  approximation — the previous one left the arena at 56% of the screen.
- Grid presets are ~1.5:1, not 16:9, **on purpose**: at a tilt the depth axis
  foreshortens, so a 16:9 grid projects far wider than the window. If the arena
  ever looks letterboxed again, check the grid aspect before the camera.
- Territory is uploaded as a small RGBA `DataTexture` (r = p0, g = p1, b = laid
  wall) and eased in JS each frame, so the floor wash slides instead of snapping
  once per tick.
- Fill-rate: the bloom chain is ~8 full-screen passes, so the scene buffer is
  capped at `PIXEL_BUDGET` (2.9M px) and there is a `res` slider. Do not remove
  the cap — a 4K panel would otherwise ask for 18M px a frame.
